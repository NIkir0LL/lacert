# LACERT — Быстрый старт

Краткая инструкция для сборки, тестирования и запуска системы. Полное
описание архитектуры и протокола — в `README.md`.

## Требования

- **Go 1.22** или новее (проверить: `go version`)
- ОС: Linux, macOS или Windows
- Зависимости уже завендорены в папке `vendor/` — интернет для сборки **не нужен**

## 1. Сборка

```bash
# Из корня проекта (папка lacert)
go build ./...
```

Если возникают проблемы с загрузкой зависимостей — используйте офлайн-режим
(всё уже лежит в `vendor/`):

```bash
go build -mod=vendor ./...
```

## 2. Запуск всех тестов

```bash
go test ./...                       # обычный прогон
go test -mod=vendor ./...           # офлайн, из vendor
go test -race ./...                 # с детектором гонок данных (медленнее)
go test ./... -cover                # с покрытием
```

Ожидаемо: все 14 пакетов проходят (`ok`), падений (`FAIL`) быть не должно.

## 3. Запуск шлюза с эмулированными устройствами (без железа ESP32)

Самый простой способ увидеть систему в работе — поднять шлюз со встроенной
эмуляцией нескольких ESP32:

```bash
go build -o gatewayd ./cmd/gatewayd

LACERT_EMULATE_DEVICES=3 \
LACERT_EMULATE_INTERVAL=1s \
LACERT_LOG_SESSION_KEYS=true \
./gatewayd
```

После запуска:
- **Веб-дашборд**: http://localhost:8080
- Устройства сами зарегистрируются, проведут постквантовое рукопожатие и
  начнут слать телеметрию.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LACERT_EMULATE_DEVICES` | Сколько ESP32 эмулировать (0 = без эмуляции) | `0` |
| `LACERT_EMULATE_INTERVAL` | Период отправки телеметрии эмулятором | `2s` |
| `LACERT_LOG_SESSION_KEYS` | Показывать полные ключи в журнале ротаций (ТОЛЬКО для теста) | `false` |
| `LACERT_HTTP_ADDR` | Адрес веб-интерфейса и REST API | `:8080` |
| `LACERT_TCP_ADDR` | TCP-порт для устройств | `:7700` |
| `LACERT_MQTT_ADDR` | Порт встроенного MQTT-брокера | `:1883` |
| `LACERT_ADMIN_TOKEN` | Bearer-токен для защищённых REST-эндпоинтов (пусто = без авторизации) | пусто |
| `LACERT_PG_DSN` | DSN PostgreSQL (пусто = хранилище в памяти) | пусто |
| `LACERT_CORS_ORIGINS` | Разрешённые CORS-источники | пусто |

> **Важно про переход на реальные ESP32.** Эмуляция включается только
> переменной `LACERT_EMULATE_DEVICES`. Серверная логика от эмуляции отделена:
> при переходе на настоящие платы её переписывать не нужно — достаточно
> убрать эту переменную и подключать реальные устройства к `LACERT_TCP_ADDR`.

## 4. Основные REST-эндпоинты (для проверки вручную)

При запущенном шлюзе (по умолчанию на :8080):

```bash
curl http://localhost:8080/healthz                       # живость
curl http://localhost:8080/api/v1/devices                # список устройств
curl "http://localhost:8080/api/v1/telemetry?range=1h&limit=50"  # телеметрия
curl http://localhost:8080/api/v1/rotations              # журнал ротаций ключей
curl http://localhost:8080/api/v1/metrics                # агрегированные метрики
curl http://localhost:8080/api/v1/gateway                # публичный KEM-ключ шлюза
```

Примеры выше рассчитаны на запуск без `LACERT_ADMIN_TOKEN`, когда авторизация
выключена. Если токен задан, ко всем запросам, кроме `/healthz` и
`/api/v1/gateway`, добавьте заголовок `-H "Authorization: Bearer ТОКЕН"`.

## 5. Что проверять при тестировании

Основные механизмы, которые стоит прогнать:

1. **Постквантовое рукопожатие** — устройства переходят в `online` на дашборде.
2. **Телеметрия** — числовые значения растут/меняются на графиках.
3. **Ротация ключей** — в журнале ротаций (`/api/v1/rotations`) появляются
   записи. В тестовом режиме видны старый и новый ключ.
4. **Проверка целостности прошивки** — раз в час (или сразу при первом тике
   планировщика) устройство отвечает на challenge.
5. **Метрики** (`/api/v1/metrics`) — счётчики рукопожатий, ротаций, проверок
   прошивки, отбитых replay.

## Если что-то пошло не так

При сообщении о проблеме приложите, пожалуйста:
- версию Go (`go version`) и ОС
- команду, которую запускали
- полный вывод ошибки
- если падает тест — имя теста из вывода `go test`.
