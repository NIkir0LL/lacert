# Развёртывание на сервере (bare-metal, без Docker)

## Быстрый путь: автоматический скрипт

Распакуйте архив на сервере и из его корня (там, где `go.mod`) выполните:

```bash
sudo bash deploy/bare-metal/install.sh
```

Скрипт идемпотентен (можно перезапускать) и делает следующее:
1. Проверяет, что установлен Go ≥ 1.22.
2. Устанавливает PostgreSQL, если его нет (через `apt-get` — для RHEL/CentOS
   замените на `dnf`/`yum` вручную перед запуском, остальное не изменится).
3. Создаёт роль и базу `lacert` в PostgreSQL со случайным паролем.
4. Собирает `gatewayd` и `devicesim`, кладёт в `/opt/lacert/bin/`.
5. Создаёт системного пользователя `lacert` (без шелла, без home).
6. Генерирует `/etc/lacert/gatewayd.env` со случайным `LACERT_ADMIN_TOKEN`
   (права `600`, читает только пользователь `lacert`) — **если файл уже
   существует, скрипт его не перезатирает**, чтобы не потерять токен/пароль
   при повторном запуске.
7. Устанавливает и запускает systemd-сервис `lacert-gatewayd`.

В конце скрипт выведет команды для проверки и напомнит открыть порты в
файрволе.

## Проверка после установки

```bash
# Статус и логи сервиса
systemctl status lacert-gatewayd
journalctl -u lacert-gatewayd -f

# Живость
curl -s http://localhost:8080/healthz

# Публичный ключ шлюза (всегда открыт, без токена — нужен для провижининга устройств)
curl -s http://localhost:8080/api/v1/gateway

# Посмотреть admin-токен и параметры подключения к БД
cat /etc/lacert/gatewayd.env

# Список устройств (требует токен из файла выше)
curl -s -H "Authorization: Bearer <ВАШ_ТОКЕН>" http://localhost:8080/api/v1/devices
```

### Веб-интерфейс

Откройте в браузере `http://<адрес_сервера>:8080/` — страница (HTML/CSS/JS)
встроена прямо в бинарник `gatewayd` и раздаётся им же, на том же порту, что
и REST API: отдельно собирать или разворачивать фронтенд не нужно. При
открытом REST API (если задан `LACERT_ADMIN_TOKEN`) страница сама покажет
баннер с предложением ввести токен — он сохраняется только в браузере
(localStorage) и не передаётся никуда, кроме заголовка `Authorization`
запросов к этому же шлюзу.

Возможности страницы: список устройств с онлайн-статусом в реальном
времени и кратким превью последнего сообщения. Регистрация нового
устройства (можно вставить строку с Serial-порта целиком — поля заполнятся
автоматически). Карточка устройства с полным последним сообщением и
журналом событий, где важные записи выделены цветом: красным — отказы и
отзыв, бирюзовым — то, что требует внимания оператора, но поломкой не
является. **Раздел «Мониторинг»** — графики числовых полей
телеметрии во времени (общий обзор по всем устройствам или конкретное
устройство, период 30 мин/1/6/12/24 часа или произвольный) плюс история
принятых пакетов. **Раздел «Журнал ротаций»** — все попытки смены ключа,
успешные и неудачные.

### Дашборд мониторинга и журнал ротаций

- **Мониторинг**: без выбора устройства — общий обзор (один график на
  метрику со всеми устройствами как отдельными линиями). С выбором
  устройства — графики только по нему плюс таблица истории принятых
  пакетов за тот же период.
- **Журнал ротаций**: старый/новый ключ показываются полностью только если
  на шлюзе включён `LACERT_LOG_SESSION_KEYS=true` (переменная
  закомментирована по умолчанию в `gatewayd.env` — см. ниже). В проде
  оставляйте выключенным, страница сама покажет баннер о том, что значения
  скрыты.
- **Проверки прошивки**: сводка (сколько проверок целостности пройдено и
  сколько отклонено) и таблица по всем устройствам. Шлюз периодически шлёт
  устройству challenge, устройство отвечает подписью от
  `challenge || SHA-256(образ прошивки)` — так подтверждается, что на плате
  работает та же прошивка, что была зарегистрирована.

### Тестовый прогон без реального железа (встроенная эмуляция)

Если хочется сразу увидеть в интерфейсе "живые" устройства, не дожидаясь
реальных ESP32, раскомментируйте в `/etc/lacert/gatewayd.env`:
```
LACERT_EMULATE_DEVICES=2
LACERT_EMULATE_INTERVAL=2s
# опционально, только для отладки — см. выше про журнал ротаций:
# LACERT_LOG_SESSION_KEYS=true
```
и перезапустите сервис: `sudo systemctl restart lacert-gatewayd`. Шлюз сам
поднимет указанное число программных устройств, которые зарегистрируются,
проведут рукопожатие и будут слать телеметрию — по тому же самому TCP/REST
протоколу, что и настоящая плата. **Когда дойдёте до тестов с реальными
ESP32 — просто убедитесь, что `LACERT_EMULATE_DEVICES` не задан (или равен
0)** и подключайте платы к порту 7700: ни шлюз, ни протокол менять не
нужно — для них эмулированное и настоящее устройство неотличимы.

> **Важно: эмуляторы стирают свои данные при каждом перезапуске шлюза.**
> Эмулированное устройство генерирует новые ключи при старте процесса, поэтому
> шлюз перед запуском эмуляции удаляет прежние записи `emulated-esp32-N` —
> вместе с их телеметрией, ротациями и событиями (иначе регистрация под тем же
> ID отклонялась бы, и устройства навсегда остались бы offline). Выглядит это
> как «пропали данные после рестарта»: счётчики в БД резко падают. **Записи
> реальных плат при этом не трогаются.** Если данные нужно накапливать —
> выключите эмуляцию (`LACERT_EMULATE_DEVICES=0`).

### Полный сквозной тест (симулятор устройства против реального шлюза)

```bash
TOKEN=$(grep LACERT_ADMIN_TOKEN /etc/lacert/gatewayd.env | cut -d= -f2)
LACERT_ADMIN_TOKEN="$TOKEN" LACERT_DEVICE_ID="test-device-1" /opt/lacert/bin/devicesim
```

Должно появиться по порядку: подготовка ключей → регистрация через REST →
рукопожатие → периодическая отправка телеметрии. Остановить — `Ctrl+C`.

Проверить, что устройство видно как "online" в REST API (в отдельном
терминале, пока `devicesim` работает):
```bash
curl -s -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/v1/devices/test-device-1
```

Проверить доставку телеметрии в MQTT (если установлен `mosquitto-clients`:
`sudo apt-get install -y mosquitto-clients`):
```bash
mosquitto_sub -h localhost -p 1883 -t 'devices/+/telemetry' -v \\
  -u "$(sudo grep -oP '(?<=^LACERT_MQTT_USER=).+' /etc/lacert/gatewayd.env)" \\
  -P "$(sudo grep -oP '(?<=^LACERT_MQTT_PASSWORD=).+' /etc/lacert/gatewayd.env)"
```

## Подключение реальных плат ESP32

Прошивка лежит в `firmware/`. Со стороны сервера дополнительной настройки не
нужно — платы подключаются к тем же портам, что и эмуляторы.

Что понадобится вписать в прошивку (`firmware/main/main.c`):

- **IP сервера** в локальной сети (`hostname -I | awk '{print $1}'`)
- **admin-токен** (`sudo grep LACERT_ADMIN_TOKEN /etc/lacert/gatewayd.env`)
- **уникальный `LACERT_DEVICE_ID` для каждой платы** — под одним ID шлюз хранит
  один набор ключей, и вторая плата с тем же ID не пройдёт рукопожатие
- параметры WiFi (только 2.4 ГГц — ESP32 не видит сети 5 ГГц).

Дальше плата всё делает сама: генерирует ключи при первом включении (хранит в
NVS), считает SHA-256 своей прошивки, регистрируется через REST и проводит
рукопожатие. Вручную «доставать ключи» и «считать хеш» не требуется.

Проверьте, что порты доступны из локальной сети (см. следующий раздел) и что
шлюз слушает все интерфейсы (`:7700`, а не `127.0.0.1:7700`).

Сборка и заливка, а также разбор частых проблем — в [`FIRMWARE_BUILD.md`](FIRMWARE_BUILD.md)
устройство прошивки — в [`FIRMWARE.md`](FIRMWARE.md).

## Полный список настроек

Все переменные окружения шлюза с значениями по умолчанию описаны в
[`CONFIG.md`](CONFIG.md) — там же готовые примеры боевой и
демонстрационной конфигурации.

## Открыть порты в файрволе

Если устройства или веб-страница будут подключаться **извне** сервера:
```bash
sudo ufw allow 7700/tcp   # TCP-протокол LACERT (устройства)
sudo ufw allow 8080/tcp   # REST API
sudo ufw allow 1883/tcp   # MQTT
```
Если всё (шлюз + устройства + веб-страница) будет работать только на самом
сервере или в одной приватной сети за NAT/VPN — открывать порты во внешний
интернет не обязательно.

## Ручная установка (если автоматический скрипт не подошёл)

```bash
# 1. PostgreSQL
sudo apt-get install -y postgresql
sudo -u postgres psql -c "CREATE ROLE lacert WITH LOGIN PASSWORD 'ВАШ_ПАРОЛЬ';"
sudo -u postgres psql -c "CREATE DATABASE lacert OWNER lacert;"

# 2. Сборка
go build -o gatewayd ./cmd/gatewayd
go build -o devicesim ./cmd/devicesim
sudo install -m 0755 gatewayd /opt/lacert/bin/gatewayd
sudo install -m 0755 devicesim /opt/lacert/bin/devicesim

# 3. Конфигурация
sudo mkdir -p /etc/lacert
sudo tee /etc/lacert/gatewayd.env <<'EOF'
LACERT_PG_DSN=host=localhost user=lacert password=ВАШ_ПАРОЛЬ dbname=lacert port=5432 sslmode=disable
LACERT_TCP_ADDR=:7700
LACERT_HTTP_ADDR=:8080
LACERT_MQTT_ADDR=:1883
LACERT_ADMIN_TOKEN=сгенерируйте_через_openssl_rand_-hex_32
# Кросс-доменные запросы по умолчанию не разрешены: дашборд отдаётся тем же
# процессом с того же адреса и в них не нуждается. Раскомментируйте только если
# к REST API обращается сторонняя веб-страница, и укажите её адрес, а не "*".
# LACERT_CORS_ORIGINS=https://lacert.example.com
EOF
sudo chmod 600 /etc/lacert/gatewayd.env

# 4. systemd
sudo cp deploy/systemd/lacert-gatewayd.service /etc/systemd/system/
sudo useradd --system --no-create-home --shell /usr/sbin/nologin lacert
sudo chown -R lacert:lacert /opt/lacert /etc/lacert/gatewayd.env
sudo systemctl daemon-reload
sudo systemctl enable --now lacert-gatewayd
```

## Типичные проблемы

**`go.mod` содержит строки `replace golang.org/x/... => github.com/...` —
это нормально.** Они появились при разработке в изолированной песочнице без
доступа к доменам вроде `golang.org`/`gorm.io`/`go.uber.org`. На вашем
сервере с обычным интернетом они не мешают — `go build` просто возьмёт код
тех же библиотек с зеркал на GitHub. Трогать не нужно.

**`go build` падает с ошибкой про версию Go.** Нужен Go ≥ 1.22.2 — проверьте
`go version`. При необходимости обновите Go (например, через
https://go.dev/dl/ — стандартная установка тарболом в `/usr/local/go`).

**PostgreSQL: `password authentication failed`.** Обычно значит, что в
`/etc/lacert/gatewayd.env` пароль не совпадает с тем, что задан роли в
PostgreSQL. Проверьте/пересоздайте пароль роли:
```bash
sudo -u postgres psql -c "ALTER ROLE lacert WITH PASSWORD 'НОВЫЙ_ПАРОЛЬ';"
```
и обновите `LACERT_PG_DSN` в env-файле соответственно, затем
`sudo systemctl restart lacert-gatewayd`.

**Сервис не стартует / сразу падает.** Смотрите подробности:
```bash
journalctl -u lacert-gatewayd -n 50 --no-pager
```
Самые частые причины: порт уже занят (`lsof -i :8080` /
`lsof -i :7700` / `lsof -i :1883`), неверный DSN, нет прав на чтение
env-файла у пользователя `lacert`.

**Обновил версию — дашборд пустой / данные «не берутся» из БД.** Три обычные
причины, по убыванию частоты:

1. **Кеш браузера.** Дашборд (HTML/CSS/JS) вшит в бинарник через `go:embed`,
   и после обновления браузер может отдавать старые файлы. Нажмите
   `Ctrl+Shift+R` (жёсткое обновление) или откройте в приватном окне.
2. **Фильтр периода.** На вкладке «Мониторинг» по умолчанию стоит «1 час».
   Если платы после рестарта ещё не прислали свежую телеметрию, графики будут
   пустыми, хотя в БД лежит история за сутки. Переключите на «24 часа».
3. **Шлюз запущен без переменных окружения.** Если запускать бинарник вручную
   (`./gatewayd`), переменные из `/etc/lacert/gatewayd.env` **не подхватятся**,
   `LACERT_PG_DSN` окажется пустым, и шлюз молча уйдёт на in-memory хранилище —
   БД он читать не будет. В логе при старте будет строка про in-memory.
   Правильное обновление версии — распаковать новый архив и выполнить из его
   корня тот же скрипт установки:

```bash
sudo bash deploy/bare-metal/install.sh
```

   Скрипт идемпотентен: пароль базы и admin-токен берутся из существующего
   `/etc/lacert/gatewayd.env`, данные в PostgreSQL не затрагиваются, служба
   перезапускается на новом двоичном файле.

   Либо вручную, если сборка выполняется отдельно:

```bash
go build -o gatewayd ./cmd/gatewayd
sudo systemctl stop lacert-gatewayd
sudo cp gatewayd /opt/lacert/bin/gatewayd
sudo systemctl start lacert-gatewayd
```

   Если нужно запустить вручную для отладки — подтяните окружение явно:

```bash
sudo bash -c 'set -a; source /etc/lacert/gatewayd.env; set +a; /opt/lacert/bin/gatewayd'
```

Проверить, какое окружение видит работающий процесс:

```bash
sudo cat /proc/$(pgrep -x gatewayd)/environ | tr '\0' '\n' | grep LACERT
```

**Резко упало число записей телеметрии после рестарта.** Скорее всего включена
эмуляция (`LACERT_EMULATE_DEVICES`): её устройства при каждом запуске шлюза
пересоздаются, и их прежние данные удаляются. Записи реальных плат не
затрагиваются. См. раздел про встроенную эмуляцию выше.

**Хочу сбросить и начать заново.** Скрипт безопасно перезапускать. Для
полного сброса (включая БД и токен):
```bash
sudo systemctl stop lacert-gatewayd
sudo -u postgres psql -c "DROP DATABASE IF EXISTS lacert;"
sudo -u postgres psql -c "DROP ROLE IF EXISTS lacert;"
sudo rm -rf /etc/lacert /opt/lacert
sudo bash deploy/bare-metal/install.sh
```
