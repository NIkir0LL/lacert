# История изменений

## v1.1.0 — 2026-07-27

Закрыт доступ к служебным данным REST API. Протокол и прошивка не менялись,
обновление обратно совместимо.

### Изменено
- `GET /api/v1/metrics` теперь требует Bearer-токен, если он задан на шлюзе.
  Раньше счётчики работы шлюза (устройства, рукопожатия, отказы проверки
  прошивки) отдавались любому. Дашборд и `stresstest` токен уже передавали,
  поэтому для них ничего не меняется.
- `GET /api/v1/gateway` остаётся открытым, потому что прошивка обращается к нему
  до рукопожатия, но служебное поле `log_session_keys` отдаётся только по
  токену. Знать, пишет ли шлюз сеансовые ключи в журнал, посторонним незачем.
- Кросс-доменные запросы по умолчанию больше не разрешены. Раньше при незаданном
  `LACERT_CORS_ORIGINS` подставлялось `*`, то есть любой сайт в браузере
  пользователя мог обращаться к API шлюза. Встроенный дашборд работает с того же
  адреса и в этих разрешениях не нуждается. Чтобы открыть доступ конкретным
  внешним источникам, перечислите их в `LACERT_CORS_ORIGINS`.
- Дашборд запрашивает сведения о шлюзе с токеном и обновляет их при его смене.
  Баннер режима журналирования ключей теперь различает три состояния, включая
  «неизвестно», и не утверждает лишнего, когда токен не введён.

### Документация
- В `GATEWAY.md` уточнено, какие эндпоинты открыты и почему `/api/v1/gateway`
  остаётся без авторизации.
- В README исправлено описание модели доверия. Раньше говорилось, что публичный
  ключ шлюза передаётся устройству офлайн, тогда как спецификация и прошивка
  описывают получение ключа по REST. Теперь сказано точно: аутентификация
  односторонняя, встречной подписи шлюза протокол не проверяет.
- В `CONFIG.md` описано новое поведение `LACERT_CORS_ORIGINS`, в `QUICKSTART.md`
  добавлено пояснение про заголовок авторизации.

### Внешний вид
- Заголовки групп на вкладке «Метрики» («Рукопожатия», «Ротация ключей» и
  далее) выровнены по центру. Раньше они прижимались к левому краю, тогда как
  содержимое карточек под ними отцентровано, и заголовок выбивался из сетки.

### Развёртывание
- `deploy/bare-metal/install.sh` больше не записывает `LACERT_CORS_ORIGINS=*` в
  файл настроек. Прежний скрипт сам открывал REST API любому сайту, из-за чего
  ограничение по умолчанию на реальном сервере не работало. Строка оставлена
  закомментированным примером с явным адресом.
- При обновлении уже развёрнутого шлюза скрипт не правит файл настроек
  оператора, но предупреждает, если в нём осталось `LACERT_CORS_ORIGINS=*`, и
  показывает команду для удаления строки.
- В `DEPLOY.md` (обе локали) пример файла настроек приведён в соответствие.

## v1.0.0 — 2026-07-22

Первый публичный выпуск. Локальный, без облака, постквантовый шлюз для
подключения IoT-устройств к корпоративной сети. Весь стек работает на
собственном сервере.

### Возможности
- Постквантовый обмен ключами ML-KEM-1024, рукопожатие в стиле Noise_XX
  (устройство аутентифицируется шлюзу efuse-привязанным ключом ECDSA P-256,
  шлюз доверенный по провижинингу).
- Непрерывная ротация сессионного ключа с подмешиванием свежего секрета
  ML-KEM — прямая секретность и устойчивость после компрометации.
- Шифрование данных ChaCha20-Poly1305, вывод ключей BLAKE3.
- Защита пакетов данных от повторного воспроизведения (окно nonce на сессию).
- Удалённая проверка целостности прошивки (ECDSA challenge-response).
- Отзыв устройств, журнал ротаций и событий, метрики.

### Состав
- Демон шлюза (`cmd/gatewayd`), реестр устройств, хранилище телеметрии
  (PostgreSQL либо in-memory), встроенный MQTT-брокер.
- REST API на chi с аутентификацией по Bearer-токену и веб-дашборд мониторинга.
- Развёртывание на bare-metal + systemd, установочный скрипт.
- Полная документация на русском и английском (`docs/ru`, `docs/en`).
