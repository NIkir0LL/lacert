# История изменений

## v1.0.4 — 2026-07-25

Приведён в порядок комментарий в коде прошивки.

### Изменено
- Шапка `firmware/main/lacert_client.c` больше не говорит, что часть
  крипто-вызовов остаётся заглушками. Реализация давно полная, и комментарий
  теперь перечисляет, на чём она построена — mbedTLS, BLAKE3 и ML-KEM из
  PQClean.

## v1.0.3 — 2026-07-24

Уточнение описания проверки целостности прошивки.

### Изменено
- В README проверка целостности прошивки больше не привязана к ECDSA. Она идёт
  по схеме «запрос-ответ» с подписью ключом устройства, а значит работает и с
  постквантовой SLH-DSA, и с Ed25519 — тем алгоритмом, который выбран для
  устройства.

## v1.0.2 — 2026-07-23

Уточнение инструкций по сборке прошивки.

### Изменено
- В `FIRMWARE_BUILD.md` и `LINUX_DEBUG.md` добавлено пояснение к путям. Команды
  записаны для монорепозитория, где прошивка лежит в `firmware/`, а в отдельном
  репозитории прошивки она находится в корне. Раньше читатель второго
  репозитория спотыкался на шаге `cd firmware`.

## v1.0.1 — 2026-07-22

Выпуск наводит порядок в документации и лицензиях. Код шлюза не менялся.

### Изменено
- `THIRD_PARTY_LICENSES.md` приведён в соответствие с фактическим состоянием
  репозитория: зависимости подключаются через Go modules.
- Документация обновлена: в спецификацию протокола добавлено описание
  устаревшего кадра типа 4, в обзоре уточнён коэффициент замедления SLH-DSA
  по фактическим замерам (9300× против ECDSA), добавлена англоязычная методика
  замеров на платах (`BOARD_MEASUREMENTS.md`).
- Год в лицензиях и уведомлениях обновлён.

## v1.0.0 — 2026-07-22

Первый публичный выпуск. Локальный, без облака, постквантовый шлюз для
подключения IoT-устройств к корпоративной сети. Весь стек работает на
собственном сервере.

### Возможности
- Постквантовый обмен ключами ML-KEM-1024, рукопожатие в стиле Noise_XX
  (устройство аутентифицируется шлюзу efuse-привязанным ключом ECDSA P-256,
  шлюз доверенный по провижинингу).
- Непрерывная ротация сессионного ключа с подмешиванием свежего секрета
  ML-KEM — прямая секретность и устойчивость после компрометации.
- Шифрование данных ChaCha20-Poly1305, вывод ключей BLAKE3.
- Защита пакетов данных от повторного воспроизведения (окно nonce на сессию).
- Удалённая проверка целостности прошивки (ECDSA challenge-response).
- Отзыв устройств, журнал ротаций и событий, метрики.

### Состав
- Демон шлюза (`cmd/gatewayd`), реестр устройств, хранилище телеметрии
  (PostgreSQL либо in-memory), встроенный MQTT-брокер.
- REST API на chi с аутентификацией по Bearer-токену и веб-дашборд мониторинга.
- Развёртывание на bare-metal + systemd, установочный скрипт.
- Полная документация на русском и английском (`docs/ru`, `docs/en`).
