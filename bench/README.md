# Прошивка для замеров криптографии

Отдельный проект: собирается и заливается независимо от боевой прошивки, сети не
поднимает, протокол не выполняет. Только вычисления.

## Зачем отдельно

Радиомодуль и обращения к флеш вносят разброс, заметный на фоне десятков
миллисекунд. Здесь их нет вовсе. И набор алгоритмов шире рабочего: часть из них
в протоколе не используется, но нужна для сравнения.

## Что меряется

**Классические примитивы**

| Операция | Зачем |
|----------|-------|
| ECDSA P-256: генерация ключа, подпись, проверка | основной набор протокола |
| ECDH P-256: генерация ключа, умножение точки | **раньше мерялось косвенно**, см. ниже |
| X25519: генерация ключа, умножение точки | для оценки гибридной схемы BSI |
| SHA-256, BLAKE3, ChaCha20-Poly1305 | симметричная часть |

**Постквантовые**

| Алгоритм | Зачем |
|----------|-------|
| ML-KEM-512, 768, 1024 | цена уровня стойкости, в протоколе используется 1024 |
| ML-DSA-44, 65, 87 | **на кристалле не мерялись ни разу** |
| SLH-DSA-128s | **мерялась только на сервере** |

### Что закрывает этот набор

**ECDH.** В работе разница между платами по ECDH составляет 1,05 раза, но
число выведено косвенно — из времени рукопожатия DTLS-ECDHE-PSK, в
предположении, что симметричная часть на его фоне мала. Здесь меряются две
вещи: умножение точки на скаляр (сама операция, которую и должен ускорять
аппаратный блок) и та же кривая через общий интерфейс. Если умножение на C6
быстрое, а разницы в рукопожатии нет, причина в обвязке mbedTLS, а не в
кристалле.

**X25519.** Немецкий стандарт BSI TR-02102 рекомендует гибридную схему
X25519 + ML-KEM вместо чистого перехода на постквантовую. В работе выбран
чистый ML-KEM, среди прочего потому, что классическая половина стоит на ESP32
дорого. Замер даёт этому выбору числовое основание вместо ссылки на общее
соображение.

**ML-DSA.** В работе сказано, что ML-DSA намного быстрее SLH-DSA, но замеров
не приводится. Здесь они появятся, причём для всех трёх уровней.

**SLH-DSA.** До сих пор мерялась только на сервере: 234,3 мс на подпись. Важная
оговорка: то число получено Go-реализацией из библиотеки circl, а здесь
считает PQClean на C. Это разные реализации, и сравнивать их напрямую как «одно
и то же на разных платформах» нельзя. Сопоставимы только числа, снятые одной
реализацией.

## Расход стека — отдельный результат

Эталонные реализации PQClean держат развёрнутые структуры на стеке целиком.
Замер через `-fstack-usage` даёт размер крупнейшего кадра:

| Алгоритм | Крупнейший кадр |
|----------|-----------------|
| ML-DSA-87 | 121 КБ |
| ML-DSA-65 | 78 КБ |
| ML-DSA-44 | 51 КБ |
| SLH-DSA-128s | менее 1 КБ |

Отсюда практический вывод: ML-DSA-87 в эталонной реализации на ESP32
неприменим без переработки библиотеки — одному вызову нужно стека больше, чем
многие задачи получают целиком. У SLH-DSA обратная картина: медленно, но по
стеку почти бесплатно.

Поэтому каждое семейство выполняется в своей задаче со своим стеком: держать
152 КБ всё время прогона незачем, а одновременно нужен только один такой стек.
Если задача не создалась — не хватило кучи, прошивка сообщит и продолжит с
остальными наборами.

Фактический расход прошивка печатает сама после каждого набора, так что запас
видно, а не приходится угадывать.

## Сборка

```bash
./scripts/fetch-components.sh     # один раз: скачать PQClean и BLAKE3
idf.py set-target esp32c6         # или esp32s3
idf.py build flash monitor
```

Чужой код в репозитории не хранится, версии зафиксированы в скрипте.

При смене платы обязательно:

```bash
rm -f sdkconfig
idf.py fullclean
idf.py set-target esp32s3
```

Без удаления `sdkconfig` смена цели не всегда применяется, и можно собрать под
прежний кристалл, не заметив этого. Проверить:

```bash
grep -m1 "^CONFIG_IDF_TARGET=" sdkconfig
```

## Настройки прогона

В начале `main/bench_main.c` наборы включаются по отдельности:

```c
#define BENCH_CLASSIC   1
#define BENCH_MLKEM     1
#define BENCH_MLDSA     1
#define BENCH_SLHDSA    1   // медленно: минуты
```

SLH-DSA стоит выключить, если нужен быстрый прогон: одна подпись идёт секунды.

Сторожевой таймер задач в этой прошивке выключен намеренно — прервать
вычисление посреди операции нельзя, а обслуживать здесь нечего.

## Что делать с результатами

Вывод монитора целиком переносится в
[`docs/ru/ECC_ACCELERATOR.md`](../docs/ru/ECC_ACCELERATOR.md) для эксперимента с
ускорителем и в `docs/ru/MEASUREMENTS.md` для остальных чисел.

Формат строки одинаков для всех операций, поэтому три прогона (C6 с
ускорителем, C6 без него, S3) сводятся в таблицу без ручного разбора.
